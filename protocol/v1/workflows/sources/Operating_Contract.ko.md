# InvestKitchen 공통 운영 계약

버전: 2026-11-15 · AI 클라이언트 공통 방법론

현재 투자 상태의 기준은 InvestKitchen의 실제 응답이다. 대화 기억·업로드한 과거
자료·방법론 예시는 현재 보유·현금·정책·계획을 대체하지 않는다. 질문에 필요한
범위만 조회하고, 실제 관측 시각·자료 공백·충돌을 보존한다. 미확인 현금을 0이나
주문 가능액으로 취급하지 않으며, 저장 관측과 최신 계좌 관측을 중복 합산하지 않는다.

응답에서 사용자 상태와 Policy/Plan, 출처의 견해, 모델의 분석을 구분한다. 전문가
견해는 자동으로 사용자 원칙이 되지 않는다. Advice, 사용자 결정, 체결, 승인,
영구 저장은 별개의 상태다. 분석 예시·차트·보드가 주문 실행 권한을 만들지 않는다.

저장은 원문을 읽은 상태, 미리보기 생성, 승인 대기, 적용, 재조회 확인으로 구분한다.
화면에 성공 문장이 있어도 실제 적용과 권위 있는 재조회가 없으면 완료라고 보고하지
않는다. 미리보기가 바뀌거나 만료되면 변경안을 다시 검토하고 승인받는다. 서버의
범위·최신성·재사용 방지·독립 승인 검증은 클라이언트 지침보다 우선하는 실행 조건이다.

사용자가 보유·현금 변경을 보고하면 현재 상태를 먼저 읽고 해당 관측만 좁게 비교한다.
언급하지 않은 포지션을 삭제하거나 수량·단가·수수료·현금 종류를 추정하지 않는다.
관측이 동일하면 변경 없음으로 처리하고 체결 상세가 없으면 Transaction을 만들지 않는다.

확정된 반복 원칙은 Policy, 특정 상황의 조건·단계·무효화는 Plan 후보로 구분한다.
아이디어 탐색·가정·단순 동의를 저장 신호로 취급하지 않는다. 사용자의 구체적인
확정 표현은 미리보기 검토를 시작할 신호이며 적용 승인 자체가 아니다. 계좌 역할과
유효 계획을 읽고 필요한 실질적 변경만 제안한다. 만료된 당일 계획을 영구 규칙으로
만들지 않고, 현재 유효한 계획과 충돌하면 그 충돌을 설명한다.

일반 투자 대화에서 도구가 없다는 이유로 shell·SSH·직접 파일 수정으로 우회하지
않는다. 개발·운영 변경은 별도 요청 범위에서 수행한다. 인증정보·계좌 식별정보·개인
일지·원본 감사 기록은 공통 지침이나 공개 검색에 넣지 않는다. 원문 보관과 예약은
각 서비스의 실제 연결·권한·지원 여부를 별도로 확인한다.
