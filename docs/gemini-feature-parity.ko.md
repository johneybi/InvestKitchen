# Gemini 기능 범위와 검증

Gemini의 모델 변경과 서버의 기능 제공·권한·데이터 공급자는 별개다. 새 모델을
선택해도 서버가 제공하지 않는 도구나 만료된 권한이 생기지는 않는다.

이 변경은 HTTP 표면에 누락된 제품 기능을 추가한다. **구현·합성 시험 단계이며,
NAS 배포·Google 재인증·실제 Gemini 모델별 검증 완료를 의미하지 않는다.**

| 기능 | HTTP 구현 상태 | 운영 조건 |
| --- | --- | --- |
| Portfolio·최신 계좌 조회 | 기존 구현 유지 | 승인된 포트폴리오와 계좌 관측 공급자 필요 |
| 시세·OHLCV | 기존 구현 유지 | 시세 공급자 설정·자격증명 격리 필요 |
| Knowledge 읽기·검색·변경 | 기존 구현 유지 | 변경은 유효한 쓰기 grant·NAS 승인 필요 |
| Plan 조회·이력·변경 | 기존 구현 유지 | Plan 저장소·명시적 포트폴리오 범위 필요 |
| OpenItem·Policy 조회 | HTTP 추가 | 각각 openitem.read·policy.read 필요 |
| 의견 가중치·의견 종합 | HTTP 추가 | opinion.read, 종합에는 knowledge.read도 필요 |
| 판단·거래 이력 | HTTP 추가 | 각 읽기 권한·포트폴리오 범위·저장소 필요 |
| PRE/POST 복기 시작 | HTTP 추가 | reflection.session.start 필요; 영구 저장과 별개 |
| Policy·의견 가중치 변경 | HTTP·브라우저 정확한 검토 추가 | 대응 읽기·쓰기 권한, 기존 저장소, 독립 승인 필요 |
| 계좌 동기화 결과 반영 | HTTP 추가 | account.read+portfolio.update, 공급자·승인 필요 |
| SessionBrief·MaterialContext 발행 | 후속 작업 | 별도 배포에만 있는 구현을 제품 기준에 편입·검토해야 함 |
| 모니터 조회·변경 | 후속 작업 | 별도 배포의 구현·권한·읽기 결과 범위 검토 필요 |
| 종목 종합 분석·지속 브리핑 이력 | 별도 개발안 | PR #31의 미배포 기능·권한을 별도 검증해야 함 |

기존 grant는 자동 확대되지 않는다. 만료된 쓰기 grant는 도구를 노출하지 않고
호출도 거부한다. 기존 GPT stdio와 HTTP는 서로 다른 실행 경로를 유지한다.

## 사용 지침

1. 새 채팅에서 `@` 메뉴로 실제 **InvestKitchen NAS** 연결 앱을 선택한다.
   앱 이름을 일반 텍스트로 쓰는 것과 구분한다.
2. “내 계좌 전체를 조회해 줘”라고 하면 `list_portfolios`로 범위를 확인하고
   `get_portfolio_state`로 계좌 ID를 읽는다. 최신 보유·평단·평가액은
   `get_account_state`를 사용한다. 관측 시각과 미연결 계좌를 명시한다.
3. “이 원문을 지식에 등록해 줘”는 현재 도구 규격으로 미리보기를 만들고,
   실제 응답의 `approval_url`을 안내한다. 사용자가 NAS에서 승인한 뒤에만
   같은 미리보기를 적용하고 읽어서 확인한다. 원문·빈 객체·출처를 임의 수정하지 않는다.
4. “운용 정책 확인”, “의견 가중치 비교”, “판단/거래 이력 확인”, “매매 전 복기”는
   각각의 도구를 사용한다. 복기 세션 시작을 일지 저장이나 주문 실행으로 표현하지 않는다.
5. 실패 시 실제 도구 오류와 권한·공급자 미설정 상태를 구분한다. 호출하지 않은
   도구의 결과, 승인 링크, 성공 기록을 만들지 않는다.

JSON 문자열 입력 프로필은 `update` 객체를 받는 미리보기에만 적용한다.
`preview_account_sync`처럼 최상위 인수를 받는 도구는 본래 객체 규격을 유지한다.
`get_write_contract`의 `input_format`과 `canonical_input_schema`를 먼저 확인한다.

## 배포 및 검증 완료 조건

- 제품 기준에 없는 기존 기능을 개인 데이터 없이 편입하고, 합성 시험과 리뷰를 마친다.
- 배포할 고정 소스·의존성·설정 변경과 복구본을 준비한다. 현재 GPT 소스와 서비스를
  그대로 유지하고 Gemini만 전환한다. 계좌 공급자 비밀정보는 MCP에 제공하지 않는다.
- 운영자가 승인한 읽기/쓰기 범위와 만료를 명시한다. 권한 갱신을 코드 배포로 대체하지 않는다.
- Gemini 계정의 실제 사용 가능한 모델별로 새 채팅·반복 호출을 시험한다.
  개발자 모드의 발견 목록과 서버의 요청 도착/반환 상태를 함께 확인한다.
- 조회, Knowledge 미리보기, 정확한 승인 페이지, 승인 전 적용 거부를 확인한다.
  합성 저장소의 승인→적용→읽기 확인을 실제 원본 데이터 변경과 구분한다.
- 다른 PC의 같은 Google 계정에서도 연결 앱을 선택한 자연어 요청을 검증한다.
- GPT 커넥터도 다시 호출해 회귀를 확인한다. NAS 재부팅 시험은 별도 운영 일정으로 잡는다.

Google 공식 안내는 맞춤 앱을 웹에서 등록한 뒤 웹·모바일에서 사용할 수 있고,
`@` 선택으로 사용을 명시할 수 있다고 설명한다. 현재 지역·언어·계정 조건은
[공식 맞춤 앱 안내](https://support.google.com/gemini/answer/17209137?hl=en)에서 확인한다.
특정 모델명이나 계정에 없는 모델의 호환성을 검증했다고 주장하지 않는다.
