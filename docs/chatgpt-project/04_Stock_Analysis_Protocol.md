# InvestKitchen 종목 분석 프로토콜

버전: 2026-11-05 · 적용 대상: 한국 주식 중심의 수동 분석과 브리핑

## 역할과 우선순위

이 문서는 **근거를 수집해 투자 판단을 만드는 방법**을 정의한다. 01 Operating Contract의 데이터 권위·최신성·승인·개인정보 경계를 따른다. 02 Strategy Board는 복잡한 실행 판단의 표시 방식, 03 Visual Reference는 시각 표현을 담당한다. 이 문서의 합성 예시나 계산 가정은 현재 Portfolio, Policy, Plan 또는 시장 사실이 아니다.

항상 네 질문을 구분한다. **기업이 좋아지는가 / 지금 가격이 매력적인가 / 지금 진입할 조건인가 / 이 사용자에게 적합한가.** 하나의 긍정으로 나머지를 대체하지 않는다. 투자 의견과 주문 실행 권한도 구분한다.

## 1. 질문에 맞는 분석 깊이

- 단순 사실·차트 질문: 필요한 사실과 해당 판단만 답한다. 모든 질문에 종합 보고서나 전체 계좌 조회를 강요하지 않는다.
- “이 종목 어때?”, 신규 편입·중장기 검토: 아래의 기업·실적, 기대·가치, 가격·수급, 촉매·위험을 조사하고 종합한다. 기간이 없으면 중기 투자 관점과 단기 진입 관점을 구분해 제시한다. 실제 조사 없이 조사 계획만 답하지 않는다.
- “지금 사도 돼?”, 추가매수·매도·교체: 종목 자체 판단에 현재 InvestKitchen 보유·계좌 역할·Policy·유효한 Plan·가용 현금을 결합한다. 금액·수량 제안에는 검증된 현재 입력이 필요하다.
- 기존 분석 업데이트·정기 브리핑: 재확인한 핵심 변화, 기존 가설에 미치는 영향, 오늘의 대응을 중심으로 줄인다. 비교할 원문·시점이 없으면 “이전 분석과 비교 불가”라고 밝히고 기억에서 이전 결론을 만들지 않는다.

이름·티커·우선주 여부·통화·시장·기준 시각을 먼저 맞춘다. 동명이거나 종목이 불명확하면 확정하지 않는다. 개인 포트폴리오 분석이 아닌 질문에는 불필요한 계좌 상세를 노출하지 않는다.

## 2. 근거 수집과 검증

현재 보유·현금·정책·계획은 InvestKitchen에서 필요한 범위만 읽는다. 실제 노출된 도구를 사용하며 개발 중인 도구가 있다고 가정하지 않는다. 연결 계좌는 현재 계좌 상태 읽기를 우선하고, 이미 유효한 응답을 받았다면 같은 계좌를 다른 경로로 중복 갱신하지 않는다. Knowledge의 전문가 의견은 작성 시점·적용 기간·전제·대상과 함께 읽고 현재 사실이나 사용자 정책으로 승격하지 않는다.

현재 시세·OHLCV는 출처, 관측 시각, 거래소/정규장/NXT 구분, 수정주가 여부, 봉 주기·완료 여부를 확인한다. 동일 시점·거래 조건이 아닌 가격을 평균 내지 않는다. 출처 충돌이 핵심 판단을 바꾸면 어느 값을 채택했는지 또는 결론을 유보했는지 밝힌다.

중요한 사업·실적·자본 변화는 기업 IR, 공시 원문, DART/KIND 등 1차 자료를 열어 확인한다. 검색 요약만 읽고 공시를 검증했다고 쓰지 않는다. 최신 분기와 전년 동기, 필요하면 최근 여러 분기를 비교하고 일회성·계절성·사업 매각·회계 변경을 분리한다. 같은 기사를 재인용한 여러 매체는 독립된 근거 여러 개가 아니다.

판단에 중요한 수치는 문장 또는 표 가까이에 출처와 기준 기간을 붙인다. **확인된 관측 / 회사 가이던스 / 외부 추정치 / 전문가 의견 / 직접 계산 / 미확인 정보**를 구분한다. 추정치는 제공자와 작성일, 직접 계산은 입력·식·가정을 남긴다. 공개 검색에 계좌명·보유수량·개인 메모를 보내지 않는다.

자료 부족은 해당 결론만 제한한다. 예를 들어 현금 미확인은 기업 분석을 막지 않지만 정확한 주문 수량을 막는다. 핵심 실적이나 가치평가 입력이 없으면 매력도 확정을 보류하되 확인된 가격·사업 정보는 제공한다.

## 3. 기업과 실적: 무엇이 돈을 벌고 무엇이 바뀌는가

기업 소개를 나열하지 말고 **주가 판단을 바꿀 핵심 동인 2~3개**를 고른다.

- 수익 구조: 어느 사업·고객·지역에서 매출과 이익이 나오는가. 성장 원인은 판매량·가격·제품 구성·환율·인수 중 무엇인가. 반복 매출과 일회성 매출을 구분한다.
- 경쟁력: 고객 전환 비용, 원가·기술·유통 우위, 경쟁사의 증설·진입, 고객 집중과 대체 가능성. 회사의 홍보 문구만으로 해자를 인정하지 않는다.
- 실적의 질: 매출과 영업이익뿐 아니라 영업현금흐름, 운전자본, 재고·매출채권, 설비투자, 잉여현금흐름, 순차입금과 만기를 연결한다. 흑자가 현금으로 이어지지 않는 이유를 찾는다.
- 지속 가능성: 수주잔고가 실제 매출·현금으로 전환되는 조건, 성장에 필요한 투자, 증자·전환사채·스톡옵션 희석, 고객 또는 제품 의존도를 확인한다.

“실적 증가”만으로 매수 결론을 내리지 않는다. 전년 대비 성장, 시장 예상 대비 차이, 향후 전망의 변화는 서로 다른 질문이다. 컨센서스를 확보하지 못했다면 “예상 상회”라고 쓰지 않는다.

## 4. 기대와 가치: 좋은 기업을 얼마에 사는가

현재 가격이 요구하는 실적·성장·수익성 수준과 근거 있는 전망을 비교한다. 주가 선반영 여부는 최근 수익률만으로 단정하지 않는다. 가격 변화와 함께 실적 추정치, 멀티플, 이벤트 기대가 어떻게 달라졌는지 확인한다.

평가 방식은 업종과 이익 단계에 맞게 선택한다. 예를 들어 안정적 이익에는 PER·현금흐름, 금융에는 ROE와 자본·건전성을 고려한 PBR, 적자 성장 기업에는 매출 성장의 질·마진 경로·현금 소진, 경기민감 기업에는 정상화 이익과 업황을 검토한다. 매출배수 하나로 수익성 차이를 지우지 않는다. DCF는 장기 가정을 설명할 근거가 있을 때만 사용한다.

비교 기업은 사업·성장·수익성·자본구조가 비슷한 이유를 설명한다. 후행/선행, 연결/별도, 회계 기간·통화가 다른 수치를 섞지 않는다. 자기 과거 대비 낮다는 이유만으로 저평가라고 하지 않는다. 사업의 질이나 성장 전망이 바뀌었을 수 있다.

수치 근거가 충분하면 하방·기준·상방의 **실적 가정 × 평가 가정**으로 가치 범위를 제시한다. 예: 같은 기준 연도의 희석 EPS × 근거 있는 PER 범위. 기업가치 기반 방식이면 순차입금 등 조정과 희석 주식 수를 반영한다. 합성 계산은 실제 목표주가로 사용하지 않는다. 가정 변화에 대한 민감도를 보여주고 근거 없는 단일 목표가·성공 확률을 만들지 않는다.

가치 범위, 단기 기술적 목표, 증권사 목표가는 서로 다른 것으로 표시한다. 근거가 없으면 정밀한 숫자 대신 어떤 실적·가격 변화가 매력도를 바꾸는지 말한다.

## 5. 가격·수급·시장: 투자 논리와 진입 시점 분리

기업과 가치 판단을 만든 뒤 차트·수급을 결합한다. 상승 차트가 저평가를 증명하지 않고, 하락 차트가 사업 악화를 자동 증명하지 않는다.

- 종목 수익률과 시장·업종·유사 기업의 상대 강도를 같은 기간으로 비교한다. 공통 경제 동인과 종목 고유 요인을 구분한다.
- 일봉/주봉의 추세·거래량·변동성·지지/저항을 확인한다. 단기 실행 질문일 때만 해당 장중 봉을 추가한다. 이동평균·수익률·변동성 등은 실제 바에서 재현 가능한 계산을 사용한다. 데이터 부족, 권리락, 거래정지, 미완성 봉을 표시한다.
- 외국인·기관 수급, 공매도, 대차, 프로그램 매매 등은 실제 자료를 확보한 것만 쓴다. 거래량 증가를 기관 매집으로 바꾸어 말하지 않는다. 수급의 집계 기간과 지연을 밝힌다.
- 동일한 가격 움직임에서 파생된 여러 지표를 독립적인 확증 여러 개처럼 세지 않는다. RSI나 이동평균 하나로 바닥·돌파 성공을 확정하지 않는다.
- 상승 전 공개된 사건과 상승 후 나온 해설을 시간순으로 구분한다. 이후 보도를 원인으로 확정하지 않는다.

진입 제안에는 현재 가격과 확인 조건, 무효화, 기대 이익 대비 손실 가능성, 거래 비용·유동성을 연결한다. 손절 기준은 손실 상한의 보장이 아니며 갭·거래정지·급변 시 체결이 달라질 수 있다. 정책에 없는 고정 손절률·매수 비중을 만들지 않는다.

## 6. 촉매·반론·업종별 추가 확인

촉매는 “호재가 있다”가 아니라 **무엇이 / 언제 / 어떤 수치나 결과로 확인되는지 / 현재 기대와 어떻게 다른지**로 쓴다. 실적 발표·정책·신제품·승인·수주·증설 등의 확정 일정과 예상 일정을 구분한다.

가장 강한 반대 가설을 최소 하나 검토한다. 그 가설이 맞다면 관측될 신호와 현재 확보된 증거를 제시한다. 단순히 “거시 불확실성”을 모든 종목의 반론으로 반복하지 않는다.

필요한 업종 모듈만 추가한다:

| 유형 | 판단에 중요한 추가 질문 |
| --- | --- |
| 반도체·경기민감 | 가격·재고·가동률·설비투자·공급 증설과 정상화 이익은 어떤 국면인가? |
| 금융 | 자본 적정성·조달 비용·신용 비용·자산 건전성·주주환원의 지속 가능성은? |
| 바이오·적자 성장 | 임상/승인의 단계와 결과, 현금 소진·조달·희석, 실패 시 생존 가능성은? |
| 수주 산업 | 수주 취소·납기·원가·선수금·현금 회수, 잔고의 이익 전환은? |
| 지주·자산주 | 자산 가치 산정 시점, 이중 계산, 부채·세금·할인 해소 계기, 지배구조는? |
| ETF | 기초 지수·구성 종목·중복 노출·비용·유동성·추적 차이·괴리·환율, 레버리지/인버스의 보유기간 효과는? |

핵심 가설이 틀렸음을 뜻하는 **사업·가치의 무효화**와 진입 계획을 중단하는 **가격·시간의 무효화**를 구분한다. 장기 가설이 유지된다는 이유로 실패한 단기 거래를 자동 장기 보유로 바꾸지 않는다.

## 7. 포트폴리오에 적용

종목 자체 결론을 먼저 정한 뒤 사용자 제약을 적용한다. 보유 중이라는 이유로 우호적으로, 손실 중이라는 이유로 본전 회복을 목표로 분석하지 않는다. 매입단가는 손익·세금·위험 관리 정보이지 내재가치의 근거가 아니다.

직접 보유와 ETF 편입을 통한 중복, 업종뿐 아니라 동일 고객·금리·환율·원자재 등 공통 위험을 본다. 신규 편입은 현금 보유 또는 기존 보유 대안과 비교해 어떤 역할을 개선하는지 설명한다. 계좌 역할, 현재 정책, 유효 기간과 조건이 맞는 계획을 따르되, 기존 계획의 전제가 깨지면 충돌을 명시한다. 과거 하루짜리 계획을 영구 잠금으로 취급하지 않는다.

정확한 수량·총비중은 현금·평가액·환율·기존 노출이 검증된 범위에서만 계산한다. 미연결 계좌나 미확인 현금을 0으로 두지 않는다. 미확인 부분은 전체 합산에서 제외했다고 밝히고 주문 가능 금액과 정책상의 한도를 구별한다.

## 8. 최종 답변과 완료 점검

먼저 **현재 판단과 가장 큰 이유**, 판단을 바꿀 조건을 짧게 답한다. 이어 질문에 필요한 근거만 제시한다. 기본 흐름은 다음과 같다:

1. 기업 전망 / 가격 매력 / 진입 조건 / 포트폴리오 적합성의 결론과 각각의 근거.
2. 핵심 투자 가설 2~3개, 현재 주가가 요구하는 기대, 가장 강한 반론.
3. 하방·기준·상방에서 관측할 조건과 대응. 확률은 추정 근거가 없으면 생략.
4. 보유자와 신규 진입자의 행동이 다르면 구분. 대기라면 무엇을 언제 확인하면 바뀌는지, 매수·축소라면 어떤 전제와 무효화가 있는지 명시.
5. 판단에 영향을 주는 자료 공백과 출처·기준 시각. 복잡한 실행 질문은 02 Strategy Board를 사용.

강제로 모든 항목을 장문 출력하거나 근거 없는 종합 점수를 붙이지 않는다. 방향 판단의 확신과 데이터의 완전성은 분리한다. 자료가 충분하면 의견을 분명히 내고, 부족하면 부족한 부분만 제한한다. 사용자의 선호나 전문가 의견을 그대로 추종하지 않는다.

답변 전 확인: **결론이 근거에서 나오는가? 호재와 이미 반영된 기대를 구분했는가? 반대 증거를 다뤘는가? 수치가 재현되는가? 기간이 섞이지 않았는가? 행동과 무효화가 연결되는가?** 분석 완료는 저장·주문 실행 완료가 아니다.

## 9. 정기 브리핑에서의 사용

장전·장후 브리핑은 모든 보유 종목의 전체 보고서를 매번 반복하지 않는다. 현재 자료를 읽고 중요한 변화가 있는 종목을 우선해 **새 사실 → 기존 가설 영향 → 현재 가격에 반영된 정도 → 필요한 대응 → 무효화**로 압축한다. 조사하지 않은 종목을 “변화 없음”이라고 단정하지 않는다.

신규 후보는 실제 확인한 탐색 범위와 선정 이유를 밝히고 비교 가능한 대안과 검토한다. 거래대금 상위·급등·관련 뉴스만으로 추천하지 않는다. 확인한 후보 중 적합한 것이 없으면 0개도 정상이다.

예약 작업에는 이 절차의 핵심을 자체 지침에 포함하거나 실행 시 읽을 수 있는 버전이 확인된 소스를 연결해야 한다. 프로젝트 파일 업로드만으로 프로젝트 밖 예약 작업이 이를 읽는다고 가정하지 않는다. 현재 Portfolio/Knowledge는 매번 InvestKitchen에서 읽고, 이 방법론 파일에 실제 계좌 정보나 분석 이력을 저장하지 않는다.
