# InvestKitchen 시각 표현 공통 원칙

버전: 2026-11-16.1 · 클라이언트별 표현을 위한 데이터·정보 위계 규격

판단과 위험 상태를 먼저, 조건과 시나리오를 다음으로, 시간별·계좌별 행동을 그다음으로
배치한다. 중복 실행·추격·과도한 투입을 막는 조건은 각주에 숨기지 않는다. 상태 표시는
근거를 요약하며, 단어·색·카드 하나로 조건의 의미를 대체하지 않는다.

정보 위계는 의미의 우선순위이지 고정된 화면 순서나 9개 구획이 아니다. 질문의 깊이와
현재 화면 기능에 따라 설명·비교표·차트·조건 보드·상호작용 화면을 고른다. 단순 숫자는
짧게 답하고, 비교·가정 변경·시나리오 탐색에 도움이 되면 명시적 HTML 요청 없이도
지원되는 시각화를 사용할 수 있다. 차트 하나를 추가했다고 정보 설계가 완성된 것은 아니다.

총 유동성에서 실제 투입할 수 있는 예산, 분할 배치, 남겨둘 현금을 구분한다. 미사용
현금 전부가 결국 투자돼야 하는 것처럼 보이지 않게 한다. 예시의 가격·계좌·종목·
수량·날짜·한도·방향·확률은 현재 데이터로 재사용하지 않는다.

각 수치의 단위·기준 통화·기간·출처·관측 시각과 계산 가정을 표시한다. 시간축이 다른
자료를 같은 시점처럼 그리지 않고, 실제 관측과 시나리오를 구분한다. 필터·슬라이더는
가정을 바꾸며 실제 Portfolio·Policy·Plan을 바꾸지 않는다. 상호 배타적인 시나리오의
투입액을 합산하거나 조건부 행동을 이미 실행된 것처럼 표현하지 않는다.

ChatGPT의 지원되는 시각화와 Gemini의 지원되는 Canvas 등은 표현 수단이다. 해당
화면에 MCP·승인·갱신 기능이 있는지는 별도로 확인한다. 생성 화면은 기본적으로 관측
스냅샷이며 실제 재조회 없는 '실시간', 연결되지 않은 저장·주문 버튼을 만들지 않는다.
화면에 인증정보를 넣지 않는다. 공유·외부 발행은 별도 요청과 공개 범위를 확인한다.

중요 판단·중단 조건·근거는 상호작용 없이도 읽을 수 있게 한다. 색만으로 상태를 구분하지
않고 조작 가능한 화면은 레이블·키보드 접근·단위를 확인한다. 렌더링이 실패하면 같은
데이터와 판단을 간단한 차트·표·설명으로 전달한다. 특정 제품의 UI를 복제하는 것과
분석·승인·저장 기능의 동등성을 구분한다. 표현 수단이 달라도 판단에 필요한 정보는 같다.
