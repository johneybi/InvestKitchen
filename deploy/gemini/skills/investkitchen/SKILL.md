# InvestKitchen 연결 지침

1. 연결된 InvestKitchen 앱을 사용한다. 연결이 선택되지 않거나 도구가 없으면 그
   상태를 밝히고 `@` 메뉴에서 실제 연결 앱을 선택하도록 안내한다. 스킬은 연결·권한을
   생성하지 않는다. API 이름을 사용자가 말하도록 요구하지 않는다.
2. `get_capabilities`로 가용 기능을 확인한다. `get_workflow_protocol`이 제공되면
   요청에 맞는 workflow를 읽고 반환된 버전·원문·절차·출력 기준을 사용한다.
   - 종목 분석/비교: `stock_analysis`
   - 계좌별 실행·다음 거래일·돌파/눌림 대응: `strategy_board`
   - 자료 등록/원문 보관/거래용 발행: `knowledge_registration`
   - 계좌·보유·현금 변경 보고: `portfolio_update`
   - 원칙·조건부 대응 확정 또는 Policy/Plan 저장: `policy_plan_update`
   - 장전/장후: `briefing`
   - 행동 전/행동 후 점검: `reflection_pre` / `reflection_post`
   - 분류가 어려우면 `overview`.
3. 공통 규격의 `tool_hints`는 호출 가능하다는 증거가 아니다. 현재 목록에 있는
   도구와 실제 권한만 사용한다. 공통 규격을 읽은 상태와 실제 조회·조사·분석·저장
   완료를 구분한다. 규격 조회가 불가하면 적용 버전을 검증했다고 주장하지 않는다.
4. 계좌 ID는 `list_portfolios`와 `get_portfolio_state`에서 확인한다. 최신 연결
   계좌는 `get_account_state`를 사용하고 관측 시각·미연결 범위·중복을 구분한다.
   공개 조사에는 공개 식별자·사건만 사용한다. 개인 상태를 웹 검색에 보내지 않는다.
5. 저장은 현재 도구 스키마의 preview→실제 NAS 승인 링크→사용자 독립 승인→
   같은 preview apply→권위 있는 재조회 순서다. 문장·스킬·플랫폼 확인으로 서버
   승인을 대신하지 않는다. JSON 문자열 프로필이면 `get_write_contract`를 읽고,
   빈 객체·원문·제공된 해시를 보존한다. 기대 해시를 만들거나 오류 뒤 임의로 바꾸지 않는다.
6. 분석은 실제 확인한 근거를 사용해 완성한다. 단순 질문에 전체 보고서나 감정
   설문을 강요하지 않는다. 복기는 한 번에 질문 하나만 하고 감정·체결·과거 성향을
   만들지 않는다. 규격에 없는 기능, 읽지 않은 자료, 승인·보관·저장·예약 성공을
   꾸미지 않는다.

방법론의 원본과 업데이트는 서버가 관리한다. 이 스킬에 현재 계좌, 비밀번호, 개인
일지, 분석 이력, 과거 전략의 수치 예시를 넣지 않는다. 오래된 읽기 전용 스킬과
충돌하면 실제 도구 발견·서버 권한·현재 규격을 확인하며 임의로 쓰기를 우회하지 않는다.
